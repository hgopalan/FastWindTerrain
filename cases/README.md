# Real terrain cases

Eight 5 × 5 km domains over real ground, at wildfire locations from
[`wildfire_levelset`](https://github.com/hgopalan/wildfire_levelset). Every
other case in this repository is synthetic — a Gaussian hill or a linear
slope — and a surrogate trained on those learns Gaussian hills.

```
python3 cases/build_catalogue.py --list     # what is in the set
python3 cases/creek_fire/prepare.py         # download SRTM, derive the grid
python3 cases/creek_fire/run.py             # solve it
python3 cases/creek_fire/run.py --plane xz.png
```

Needs `pip install ".[cases]"` for the download. Nothing else here does.

## How a case is built

`casegen.py` holds all of it; each folder's `prepare.py` and `run.py` are
twenty lines that pass their own coordinates. They are generated by
`build_catalogue.py`, so a change to the implementation reaches all eight
at once — edit `casegen.py`, not a case folder.

Cell counts are the same everywhere — `(100, 100, 60)`, 50 m horizontally,
one tensor shape — but the **vertical extent follows each case's own
relief**: the floor sits at the tile's minimum elevation and the top a
kilometre above its highest ground, with the stretching ratio solved so the
column lands exactly on that top. Creek Fire gets 1334–3462 m ASL; Bootleg
gets 1387–2608 m.

## What is committed and what is not

| File | Committed | Why |
| --- | --- | --- |
| `case.json` | yes | coordinates and the download box |
| `survey.json` | yes | elevation extremes and the derived grid — a few hundred bytes |
| `prepare.py`, `run.py`, `README.md` | yes | generated, but reviewable |
| `terrain.csv` | **no** | about a megabyte per case |
| `*.tif`, `plt_*/` | **no** | intermediates and output |

Because `survey.json` is committed, `prepare.py --no-download` rebuilds a
case's grid offline and `tests/test_cases.py` runs with no network and no
geo stack.

## The thing to know before trusting a result

**The solver does not check that terrain fits inside the domain.** Terrain
below `prob_lo[2]` leaves every cell fluid with the ground under the mesh;
terrain above `prob_hi[2]` marks every column solid. Neither warns, neither
raises, and both write a perfectly plausible plotfile.

So `casegen` asserts the fit before writing anything, and `run.py` re-checks
against what the solver actually built — `straddles`, `finite`,
`divergence`, `vertical`, `speed-up`. Those are not "did it run"; they are
the five ways a real-terrain case goes quietly wrong. The first Creek Fire
download returned a tile of nodata, which the elevation reader turns into a
flawless sea-level plain, and three of the five failed rather than
reporting wind over terrain that was not there.

## Vendored files

`srtm_terrain_reader.py` and `wildfires_reference.csv` are copied verbatim
from `wildfire_levelset`. `build_catalogue.py --check-upstream` diffs them
against the raw URLs; the revisions they came from are recorded in
`UPSTREAM` in that file.
